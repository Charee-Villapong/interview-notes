# 手順書（VM側パイプライン）

対象：VM側で完結する後処理（転送受信→検証→文字起こし→合成→下書き保存→削除ガード）。
Mac側ツール（目標形G）の手順は、Mac側の前提（ディスク空き確保・画面作業の段取り）が整った段階で別途追記する。
状態と遷移条件の正本は `docs/状態管理.md`。

## データ領域

すべての実行時データは環境変数 `INTERVIEW_DATA_DIR` が指す領域に置く（リポジトリ内には置かない）。

```
$INTERVIEW_DATA_DIR/
  state/sessions.json     # セッション状態の永続化
  staging/<session_id>/   # 転送ステージング（検証前。不完全なコピーはここに留める）
  inbox/<session_id>/     # 受信検証済みの音声（処理用一時コピー）
  work/<session_id>/      # 作業用テキスト（文字起こし・合成結果）
  log/events.jsonl        # 通知・処理ログ（日付・セッションID・状態・エラー種別のみ）
```

音声フォルダ（inbox）と md の作業場所（work／notes）は分離する。md の正本はリポジトリの `notes/` の1か所に絞り、保存確認後に作業用コピーを削除する。

## 転送受信と検証

1. Mac側からの転送は、暗号化された既存の Mac―VM 間経路に限る。具体方式（V3）は実働テストで実測して確定する。現時点の実装は「ステージングへ置かれたファイル群＋マニフェスト」を検証・昇格させる受信部までを担う。
2. マニフェスト（JSON）：配置は `staging/<session_id>/manifest.json`。`session_id` と、ファイルごとに `name`／`size`／`sha256` を持つ。系統はファイル名で区別する（`system`＝相手、`mic`＝自分）。
3. 検証：全ファイルについて、ステージング上の実サイズ一致と SHA-256 一致を確認する。1件でも不一致なら転送は未完了として扱う。遷移先・再開先は正本 `docs/状態管理.md` の遷移条件表に従う。検証を通過したファイルだけを inbox へ昇格し、状態を `received` にする。
4. 再転送時はステージングを置き換える。受信検証を通過していないファイルは、処理対象に絶対に含めない（正本 `docs/状態管理.md`「二重処理・二重保存の防止」）。

## 処理ラン

- 処理ランは毎回、状態ストアを全件走査し、処理可能な状態（`transferring` の検証待ち、`received`、`needs_reprocess` の再開可能分）を取り上げる。
- 順序はコードで固定する：受信検証 → 文字起こし（2系統） → 話者合成（時系列マージ、話者A＝マイク系統＝本人、話者B＝システム系統＝先方） → 作業用テキスト生成 → 状態を `awaiting_editing` へ。
- 訂正・要約の下書き生成は判断部分であり、Claude が担う（パイプラインの自動処理には含めない）。下書きが用意されたら、保存ステップ（保存ガード付き）で `notes/` へ保存し、`draft_saved` → `awaiting_review` へ進める。
- 本人照合後の遷移（確定版の保存／再処理）は正本 `docs/状態管理.md` の遷移条件表に従う。再処理の場合は、Mac原音声からの再転送を起点とする。
- 失敗はすべて通知イベントに記録し、セッションを `needs_reprocess` に留める。再試行に上限は設けない。

## 保存ガード（GitHub保存前）

保存処理は、保存実行前に次のすべてをコードで確認する。1つでも満たさなければ保存を中止し、通知する。

1. 保存対象に音声・動画ファイル（`.m4a` `.mov` `.mkv` `.wav` `.mp3` `.aac` `.flac` `.ogg` `.opus` `.aiff` `.caf` `.mp4` `.webm`）が含まれていないこと。
2. 保存先リポジトリが非公開であること（APIで確認する。正本 `docs/状態管理.md` の遷移条件で必須とされる確認である）。

自動生成の md は冒頭に「下書き（未照合）」を明示する。照合なしに確定版を保存しない。

## 削除ガード

- VM側コピーの削除：正本 `docs/状態管理.md`「削除の条件」のとおり、処理完了（`processing` を正常終了している）**かつ** GitHub への下書き保存確認（`draft_saved` 以降の状態で、`draft_saved_at` が記録されている）の両方を満たす場合のみ、削除コマンドが実行する。満たさない場合は拒否して理由を記録する。削除後は `vm_copy_deleted_at` を記録する。
- Mac側コピーの削除可否判定：正本 `docs/状態管理.md`「削除の条件」のとおり、確定版が保存済み（`final_saved` 以降）**かつ** 未処理でないこと（`needs_reprocess` でないこと）を満たすセッションのみ「削除可」。期限（最長7日）は「いつまでに消すか」の上限であり、削除の許可条件ではない。判定はコードが行い、Mac側の実行は Mac 側の工程で行う（本手順書の範囲は判定まで）。
- 期限管理：正本 `docs/状態管理.md`「削除の条件」のとおり、録音から7日を超え、かつ `final_saved` に到達していないセッションは、削除ではなく「期限超過の未処理」として走査で可視化する（再処理の拾い直しと可視化のため）。

## STTエンジン

- 文字起こしは VM 上の whisper 系エンジンで行う前提だが、モデル選定（V1）と VM リソース確認（V2）が未了のため、現時点ではエンジンは未接続（未設定時は `stt_not_configured` として `needs_reprocess` に残り、通知される。失敗を成功として扱わない）。
- モデルは実測（60分音声の処理時間と CER）をもとに選定する。選定までは特定モデルに固定しない。
