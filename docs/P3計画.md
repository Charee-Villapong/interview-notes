# Mac側ツール（録音アプリ）の仕様と連携

Mac 常駐の自作メニューバーツール（録音アプリ）の仕様と、VM 側パイプラインとの連携をまとめる。状態・遷移・削除条件の正本は `docs/状態管理.md`、Mac→VM の受け渡し形式は `pipeline/SPEC.md` の実装契約が正本である。

- バンドル ID は `com.nishikawa.interviewrecorder` で確定し、変更しない（TCC 許可の同一性に関わる）。
- 録音の同意確認は相手方へ取らない（本人の確定方針）。

## 仕様

- 録音はシステム音声（相手）とマイク（自分）の2系統分離、音声のみ（動画なし）。
- 終了検知：停止ボタン（手動）が主。加えて5分間無音で自動停止。自動停止後の再開猶予は5分（同一セッション扱い）。安全弁として3時間で強制停止する。
- 転送：**VM 側からのプル**。VM が既存の VM→Mac 経路で Mac の録音置き場から取得し、VM 側でサイズ＋チェックサム照合を満たした時のみ転送完了とする。方式の正本は `docs/状態管理.md`「転送方式（プル方式）」、実装契約は `pipeline/SPEC.md`「PULL 追加契約」。
- Mac 側音声の削除は、確定版保存済み等の条件をコードが確認した処理済み分のみ。未処理分は日数に関わらず自動削除しない。期限（最長7日）は削除の許可条件ではなく「いつまでに消すか」の上限である。

## キャプチャ方式

標準部品のみで構成し、外部ドライバや仮想オーディオデバイスは導入しない。

| 系統 | 方式 |
|---|---|
| システム音声（相手） | ScreenCaptureKit（`SCStream`、`capturesAudio` 有効） |
| マイク（自分） | AVAudioEngine（入力タップ） |

- システム音声のキャプチャでは映像出力も登録し、映像サンプルは破棄する（詳細は `docs/P3実働手順.md`「system 音声のキャプチャと診断ファイル」）。
- 書き出し形式は両系統とも `.m4a`（AAC、48kHz、モノラル）に統一する（入力は共通部品 `AudioFileWriter` が変換してから書く）。ファイル名は `system_<session_id>.m4a`／`mic_<session_id>.m4a` とし、接頭辞による系統分類（P1 の契約）に一致させる。分類外のファイル（接頭辞が `system`／`mic` のどちらでもないもの）をセッションフォルダに作らない。
- ファイルは常に系統ごとに1本に保つ。

## 必要権限とエンタイトルメント

| 対象 | 仕組み | 必要なもの |
|---|---|---|
| マイク | TCC（Microphone） | `Info.plist` の `NSMicrophoneUsageDescription`。初回利用時に許可ダイアログが出る |
| システム音声（ScreenCaptureKit） | TCC（Screen Recording） | システム設定「プライバシーとセキュリティ > 画面収録」への追加。映像は使わないが、音声キャプチャもこの許可の対象になる |

- エンタイトルメント：App Sandbox を有効にしないローカル配布の前提では、上記のためのエンタイトルメントは原則不要（マイク用の `com.apple.security.device.audio-input` はサンドボックス配下でのみ必要）。ビルド時に `codesign -d --entitlements - <app>` の出力が空（または想定どおり）であることを確認する。
- 署名と TCC の同一性：アドホック署名のまま再ビルドすると、バイナリの同一性が変わり、付与済みの TCC 許可が失われる既知の落とし穴がある。対策として、バンドル ID を確定し、識別子ベースの指定要件（designated requirement）で署名する。再ビルド後に許可が維持されることを確認する（手順は `docs/P3実働手順.md`）。

## Mac側セッション状態と VM側11状態の対応

Mac ツールはセッションごとにメタデータ（JSON）を持ち、`state` フィールドには常に VM 側11状態の語彙だけを入れる。録音中などの Mac 内側の細かい状態は別フィールド `local_phase` に分離し、正本の状態語彙を汚さない。

| Mac側の出来事 | `local_phase` | `state`（VM語彙） | VM側との同期 |
|---|---|---|---|
| 録音開始 | `recording` | （未登録。録音完了まで VM に送らない） | なし |
| 録音中・無音が続く | `recording`（無音タイマ作動） | 同上 | なし |
| 自動停止→猶予中 | `grace` | 同上 | なし |
| 猶予内に再開 | `recording` | 同上 | なし |
| 手動停止／猶予経過／3時間到達で録音確定 | `finalizing` | `recorded` | ローカル確定のみ |
| 転送待ち（確定直後） | `ready_to_transfer` | `transfer_pending` | なし（VM 側プルが拾う） |
| 転送中（VM 側プルが取得中） | （Mac 側は変化なし） | `transferring` | VM 側プルが Mac の録音置き場から取得 |
| VM の受信検証に成功 | `uploaded`（プル後に VM 側状態を写す際） | `received` | VM 側 `receive` 相当（プル工程内の受信検証）の成否で判定 |
| 取得・検証に失敗 | `upload_failed` | `needs_reprocess`（resume: `transfer_pending`） | 次回プルで再開する |
| VM 側で処理が進んだ後 | `mirrored` | VM の現在状態を写す | `status` 照会で取得（削除判定の前に都度照会） |
| 削除可（VM 照会で確認） | `deletion_ready` | `deletable` 相当 | `mac-eligible` の終了コードで判定 |
| Mac 側コピーの削除完了 | `deleted` | `closed`（両側削除が揃った時点） | 申告手段は連携事項（下記） |

※ `mirrored` と削除可否照会の経路は現行では未整備である（「削除ガードとの連携」を参照）。

## 転送フロー（プル方式）

方式の正本は `docs/状態管理.md`「転送方式（プル方式）」、VM 側の実装契約は `pipeline/SPEC.md`「PULL 追加契約」。Mac 側の担う部分は次である。

1. セッション ID を面談日付ベースで採番する（`YYYY-MM-DD_NN`。同日の件数はローカルメタデータで数える）。
2. 録音確定後、2ファイルについて `name`／`size`／`sha256` を計算し、マニフェスト（`manifest.json`）を生成する。形式は P1 の `Manifest` と同一とする。Mac 側はここまでで転送待ち（`transfer_pending`）に留まる（自動プッシュは設定 `autoTransferEnabled=false` で無効化し、エラー表示・再試行を行わない）。
3. 以後は VM 側のプル工程が取得・照合・昇格を行う（取得済みは再取得しない。取得失敗は `transfer_fetch_failed`、検証不一致は `transfer_verification_failed` として未処理に残る）。
4. 接続先・配置先などの環境依存値は、すべて環境変数またはローカル設定ファイル（gitignore 済み）から読む。コードと文書に実値を書かない。

## 削除ガードとの連携

- Mac 側コピーの削除は、VM の CLI `mac-eligible <session_id>` が可（終了コード 0）を返したセッションに限る。判定条件の正本は `docs/状態管理.md`「削除の条件」（確定版保存済み かつ 未処理でないこと）であり、Mac 側で条件を再解釈しない。
- 期限超過の未処理（録音から7日超・`final_saved` 未到達）は、削除のためではなく可視化のために一覧へ挙げる（正本どおり）。未処理は日数に関わらず削除しない。
- Mac 側からの削除可否照会の経路は現行では未整備であり、照会できない間は削除可否を「不可」として扱う（fail-closed）。
- VM 側の `mac_copy_deleted_at` を記録し `closed` へ進めるための申告手段は現行 CLI に無いため、Mac 側メタデータに削除完了を記録するに留める。
