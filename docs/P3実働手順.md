# P3実働手順（Mac 作業セッション：ビルド→権限→試し録音→本番録音）

AI組織 Issue #11 の P3 実働を、Mac の本体画面で見える形で行うための番号付き手順。計画と確定仕様は `docs/P3計画.md`、Mac 側ツールの使い方は `mac-app/README.md` が正本で、本書は当日の進行だけを担う。

## 本人の決定（2026-11-08）と前提

- 2026-11-09 12:00〜13:00 のオンライン面談（Google Meet）の **前に**、ビルド＋権限付与＋ダミー試し録音まで済ませ、面談 **本番でも録音する**。
- バンドル ID は `com.nishikawa.interviewrecorder` で確定済み（`mac-app/Resources/Info.plist` と `signing-requirement.txt` に設定済み。変更しない）。
- 文字起こしの確定モデルは **large-v3-turbo**（VM 側。V1 で本人確定済み）。
- 権限付与（ダイアログへの応答、システム設定での追加、認証）は **本人が手動で行う**。エージェントは代行しない。
- Mac 上で実行する具体的なコマンドと設定値は、Google Drive のコマンドファイル（「Mac接続セットアップ用コマンド.txt」）の当該節に番号付きで用意してある。本書とリポジトリには実値を書かない。
- 目安：ダミー試し録音の疎通確認までを面談開始の30分前までに終える。Mac はロック解除済みの状態でセッションを始める（caffeinate 稼働中であること）。

## 既定案（判断が要る箇所の先決め）

| 項目 | 既定案 | 理由 |
|---|---|---|
| アプリ配置先 | `~/muse-tools/InterviewRecorder.app` に固定し、起動は常にここから | ScreenCheck／KeyHelper の前例どおり。配置がぶれると TCC の確認が追いにくい |
| 署名 | `mac-app/build.sh` の識別子ベース指定要件（確定済み） | 再ビルド後も TCC 許可を維持するため |
| ローカル設定 | `~/Library/Application Support/InterviewRecorder/config.json`（`config.example.json` の全キーを埋める） | コード側の読み込み先がここ。キーの欠落は読み込みエラーになるため全キーを埋める |
| 転送方式 | VM 側からのプル（本人の設計変更決定。2026-11-08） | Mac→VM の接続経路が現行構成に無いため。Mac 側は `autoTransferEnabled: false` で自動プッシュを止める |

## 手順

### A. 最新化とビルド

1. Mac のターミナル（本体画面で見えるウィンドウ）で、このリポジトリを GitHub から作業用にクローンする（Mac 側に常設クローンは置かない。コマンドは Drive のコマンドファイル参照）。
2. `mac-app/` で `./build.sh` を実行する。**初回ビルドが最初のコンパイル確認になる**（VM 側に Swift ツールチェインが無いため未確認）。エラーが出たら、その場で内容を確認して直し、再実行する。要確認箇所の一覧は `docs/P3計画.md`「静的レビュー（2026-11-08）」にある。
3. ビルド成果物 `InterviewRecorder.app` のエンタイトルメント表示が空であることを確認する（`build.sh` の末尾に出力される）。
4. 成果物を配置先（`~/muse-tools/`）へコピーする。以後の起動は常に配置先から行う。

### B. ローカル設定の配置

5. `~/Library/Application Support/InterviewRecorder/config.json` を作成し、全キーを埋める（具体値は Drive のコマンドファイルの節どおり）。特に次を確認する：
   - `autoTransferEnabled` が `false` であること（転送は VM 側プルが正。欠けると自動プッシュ有効として扱われ、失敗アラートが繰り返し出る）。
   - `remotePythonPath` が `src` であること（プッシュ経路を使う場合のリモート CLI 用。現行運用では使わないが、キーの欠落は読み込みエラーになるため埋めておく）。
   - `sshHostAlias` はキーとして埋めておく（現行運用では Mac→VM の接続自体が無いため実接続には使わない）。
6. VM→Mac の接続確認は取りまとめ側（VM 側）が行う。Mac のターミナルから VM への SSH は現行構成では成立しないため、ここでは確認しない（録音側の問題と混ぜない）。

### C. 起動と権限付与（本人の手動操作）

7. 配置先の `InterviewRecorder.app` を起動する。メニューバーに「面談レコーダー」と出ることを確認する。設定読み込みエラーでアラートが出た場合は、B の内容を見直す。
8. メニューの「録音開始」を押す。マイクの許可ダイアログが出たら **本人が許可** する。
9. 画面収録の許可案内が出たら、システム設定 > プライバシーとセキュリティ > 画面収録 で `InterviewRecorder` を追加して有効にする（**本人のクリックと認証**が要る）。映像は使わないが、システム音声のキャプチャにこの許可が要る。
10. 許可後、アプリが起動したままなら一度終了して起動し直し、もう一度「録音開始」を押して、ダイアログが再表示されずに録音が始まることを確認する。

### D. ダミー試し録音（疎通確認）

11. （任意・推奨）無音検知と猶予の確認を短時間で行うため、`config.json` の `silenceStopSeconds` と `resumeGraceSeconds` を一時的に 30 へ変え、アプリを起動し直す。
12. Mac で音声つきの動画や音楽を再生しながら、自分も声を出す（system 系統＝再生音、mic 系統＝自分の声）。「録音開始」を押し、2〜3分録る。
13. 録音中に30秒ほど無音にし、メニュー表示が「無音・猶予中」に変わること、猶予内に声を出すと録音中に戻ることを確認する。
14. メニューの「停止」を押す（手動停止が主経路）。録音が確定する（転送はこの時点では行われず、Mac ローカルに転送待ちとして残る）。
15. ローカル確認：`~/Library/Application Support/InterviewRecorder/recordings/<セッションID>/` に `system_<セッションID>.m4a` と `mic_<セッションID>.m4a` の2ファイルがあり、どちらも 0 バイトでないこと。再生して、system 側に再生音、mic 側に自分の声が入っていること。
16. VM 側確認（取りまとめ側で実施）：VM のパイプラインで `pull`（Mac から取得）を実行し、当該セッションが `status` で `received` になっていること（サイズ＋SHA-256 の受信検証通過）。
17. 文字起こし確認（取りまとめ側で実施）：確定モデル large-v3-turbo で `run` を実行し、`transcript.md` が話者ラベル付きで生成されること。
18. **設定を本番値に戻す**：手順11で変えた場合は `silenceStopSeconds` と `resumeGraceSeconds` を 300 に戻し、アプリを起動し直す。戻し忘れが本番に効くため、ここで必ず読み戻して確認する。

### E. 面談本番の録音

19. 面談の開始前に、メニューバー表示が「面談レコーダー」（待機中）であることを確認する。
20. Google Meet に参加したら（または参加直前に）、メニューの「録音開始」を押す。表示が「● 録音中」になったことを目視する。
21. 面談中はそのままでよい。**注意**：両系統とも無音が5分続くと自動停止の猶予に入り、そのまま5分過ぎると確定してしまう。もし途中で止まっていたら、再度「録音開始」を押せば続きを別セッションとして録れる（セッションが分かれることは割り切る）。
22. 面談が終わったら、速やかにメニューの「停止」を押す。転送は VM 側のプルで後から取得される（Mac 側から自動では送らない）。
23. 面談後、取りまとめ側で VM の `pull` を実行し、`status`（`received` 到達）と文字起こしの生成を確認して結果を報告する。

### F. うまくいかない時

- **system ファイルが無い／0バイト**：画面収録の許可が効いていない可能性。システム設定の画面収録リストで `InterviewRecorder` が有効か確認する。有効なのに効かない場合は、リストから一度「−」で削除し、「+」で配置先のアプリを追加し直す（アドホック署名アプリで許可が紐づかない場合の前例対応）。
- **マイクが入らない**：システム設定 > プライバシーとセキュリティ > マイク で有効か確認する。
- **転送（プル）が通らない**：セッションは Mac 側に未処理として残る（消えない）。VM 側で `pull` の失敗内容を確認する。主な切り分け：VM→Mac の SSH 疎通（取りまとめ側で接続確認）、Mac 側の録音置き場に `manifest.json` と2ファイルが揃っているか（手順15）。Mac 側アプリの「未転送分を再送する」は現行運用（プル方式）では使わない。
- **アプリが落ちた**：配置先から起動し直す。転送前のセッションは Mac 側に転送待ちとして残っており、VM 側プルが拾う。
- **ビルドをやり直した後**：配置先へコピーし直し、権限ダイアログが再表示されずに録音できること（TCC 許可の維持）を確認してから本番に使う。

### G. 再ビルド・差し替え（プル方式対応。2026-11-09 セッション用）

転送をプル方式へ変更したことに伴う Mac 側アプリの差し替え手順（自動プッシュの無効化設定の追加）。バンドル ID と署名（識別子ベース指定要件）は変えないため、付与済みの TCC 許可は維持される想定。初回配置がまだの場合は A〜C を先に行い、本節は設定追加の部分（手順4）だけを B に読み替える。

1. アプリを終了する（メニュー > 終了）。録音中でないことを確認してから行う。
2. GitHub から最新の作業用クローンを用意し、`mac-app/` で `./build.sh` を再実行する。エンタイトルメント表示が空であることを確認する。
3. 成果物 `InterviewRecorder.app` を配置先（`~/muse-tools/`）へコピーし直す（既存を置き換える）。
4. `~/Library/Application Support/InterviewRecorder/config.json` に `"autoTransferEnabled": false` を追加する（他のキーは変更しない）。追加後に JSON として読めることを確認する（キーが無い状態では自動プッシュ有効として扱われ、起動時の再送で失敗アラートが繰り返し出る）。
5. 配置先からアプリを起動し直す。**起動直後に転送失敗のアラートが出ないこと**と、メニューバー表示が「面談レコーダー」（待機中）であることを確認する。
6. メニューの「録音開始」を押し、権限ダイアログが再表示されずに録音が始まることを確認する（TCC 許可の維持確認）。そのまま D（ダミー試し録音）へ進む。
