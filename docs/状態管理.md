# 状態管理（正本）

本書は、面談セッション（1回の面談の録音とその後処理）の状態一覧と遷移条件、および各文書に共通する小ルール（保存ガード・処理順序・話者マッピング・環境変数等）の**正本**である。
企画書（AI組織 Issue #11 修正版11周目）の「状態の例」は例示であり、開発では本書を正とする。
状態名・遷移条件を変更する場合は、本書を先に改訂し、テストを追随させること。

## セッション識別子

- セッションIDは面談日付ベースとする（例：`2026-11-09_01`。同日の2件目以降は連番）。
- ファイル名・通知・処理ログには、セッションID・日付・状態・エラー種別のみを用いる。企業名・個人名・面談内容は含めない。
- フォルダは面談日付ごとに分ける（例：`2026-11-09/`）。ファイル名にも面談日付を含める。md の保存先は `notes_dir/<日付>/<session_id>.md` とし、フォルダの日付はセッションIDの日付部分（面談日付）と同一とする。

## 状態一覧

| 状態 | 意味 | 主な所在 |
|---|---|---|
| `recorded` | Mac側で録音済み（2系統の音声ファイルが揃った） | Mac |
| `transfer_pending` | 転送待ち（自動停止時は猶予経過後、手動停止時は即時に対象） | Mac |
| `transferring` | 転送中（ステージングへ受信中） | Mac→VM |
| `received` | 転送済み（VM側でサイズ＋チェックサムの受信検証を通過） | VM |
| `processing` | 処理中（文字起こし→話者合成） | VM |
| `awaiting_editing` | 訂正・要約の下書き生成待ち（判断部分。Claudeが担う） | VM |
| `draft_saved` | 下書き（未照合）の md が GitHub へ保存済み | GitHub |
| `awaiting_review` | 本人照合待ち（必須ステップ） | — |
| `final_saved` | 確定版の md が GitHub へ保存済み | GitHub |
| `deletable` | 削除可（削除条件をコードが確認済み） | Mac／VM |
| `closed` | 両側コピーの削除が完了し、セッション終了 | — |
| `needs_reprocess` | 要再処理（失敗。未処理として保持し、毎ランの全件走査対象） | — |

`needs_reprocess` のレコードは、失敗したステップへ戻るための `resume_state`（再開先の状態）と、失敗の `error_kind`（種別のみ。内容は書かない）を保持する。再試行に回数上限は設けない。

## 遷移条件

| From | To | 条件（コードが機械的に確認する） |
|---|---|---|
| `recorded` | `transfer_pending` | 録音停止が確定した（手動停止、または自動停止後の猶予経過＋再開なし） |
| `transfer_pending` | `transferring` | 転送を開始した |
| `transferring` | `received` | マニフェストの全ファイルについて、受信サイズ一致かつ SHA-256 一致を VM 側で確認した |
| `transferring` | `needs_reprocess` | 転送中断・検証不一致。ステージングの不完全なコピーは処理対象にせず、再転送で置き換える（resume: `transfer_pending`） |
| `received` | `processing` | 処理ランが対象として取り上げた |
| `processing` | `awaiting_editing` | 2系統の文字起こしと話者合成（時系列マージ）が完了し、作業用テキストが生成された |
| `processing` | `needs_reprocess` | STT等の失敗（resume: `received`。起点は受信済みコピー。コピーが使えない場合は `transfer_pending` へ戻し Mac 原音声から再転送） |
| `awaiting_editing` | `draft_saved` | 下書き md の保存が完了した（保存前に保存ガード＝音声非含有チェック通過と、保存先リポジトリの非公開確認が必須） |
| `awaiting_editing` | `needs_reprocess` | 保存失敗（音声検出による中止を含む）（resume: `awaiting_editing`） |
| `draft_saved` | `awaiting_review` | 自動遷移（下書き保存の直後）。VM側コピーの削除可否はこの時点から判定できる |
| `awaiting_review` | `final_saved` | 本人照合が完了し、確定版が保存された |
| `awaiting_review` | `needs_reprocess` | 照合の結果、再処理が必要（resume: `transfer_pending`。Mac原音声から再転送して再処理する） |
| `final_saved` | `deletable` | 削除条件のコード確認を通過した（下記） |
| `deletable` | `closed` | VM側・Mac側の両コピーの削除完了を記録した |
| 任意（`closed` を除く） | `needs_reprocess` | 上記以外の失敗全般。成功していないステップを成功扱いにしない |
| `needs_reprocess` | `resume_state` の状態 | 再処理の再開。`resume_state` は失敗したステップに応じて `transfer_pending`／`received`／`awaiting_editing` のいずれか |

不正な遷移（表にない遷移）はコードが例外として拒否する。`closed` は終端状態であり、外向きの遷移を持たない。

## 削除の条件（コード担保。M1・M2）

削除処理は、実行直前に処理コードが条件を機械的に確認し、満たさなければ実行しない。

- **VM側コピーの削除条件**：処理完了（`processing` を正常終了している）**かつ** GitHub への下書き保存確認（`draft_saved` 以降の状態で、`draft_saved_at` が記録されている）の両方。
- **Mac側コピーの削除可否**：確定版が保存済み（`final_saved` 以降）**かつ** 未処理でないこと（`needs_reprocess` でないこと）。期限（最長7日）は「いつまでに消すか」の上限であり、削除の許可条件ではない。**未処理・未保存の音声は、録音から何日経っても削除対象にならない。**
- 期限超過の未処理検出：録音から7日を超え、かつ `final_saved` に到達していないセッションは「期限超過の未処理」として走査結果に挙げる（削除のためではなく、再処理の拾い直しと可視化のため）。ただし、`final_saved_at` が記録済みのセッション、状態が `final_saved`・`deletable`・`closed` のセッション（`final_saved` 以降の状態は到達済みとして扱う）、および `created_at` が無いセッション（経過日数を判定できないため）は対象外とする。

## 二重処理・二重保存の防止

- 同一セッションIDの登録は冪等（既存レコードを返し、二重に作らない）。
- 再転送時は、VM側の不完全なコピー（ステージング）を置き換え、状態は1つに保つ。
- 受信検証を通過していないファイルは、処理対象に絶対に含めない。

## 通知・ログ

- 失敗は必ず通知イベントとして記録する（silent failure 禁止）。記録項目は日付・セッションID・状態・エラー種別のみ。
- 処理ランは毎回、新規分に加えて未処理・要再処理の残件を**全件走査**して処理対象に含める。同一原因で失敗が続く件は、他件の処理を止めず、`needs_reprocess` のまま毎ランの対象であり続ける。

## 共通ルール

各文書に分散していた小ルールの定義は、本節に集約する。他の文書は本節への参照に留める。

### 音声ファイルの配置

- 音声ファイルはこのリポジトリに置かない。音声は Mac（原音声）と VM（処理用の一時コピー）にのみ置く。

### 保存ガードの拡張子リスト

- 保存対象に含まれていないことを確認する音声・動画ファイルの拡張子は、`.m4a` `.mov` `.mkv` `.wav` `.mp3` `.aac` `.flac` `.ogg` `.opus` `.aiff` `.caf` `.mp4` `.webm` とする。リポジトリ側の第二の防壁として、音声・動画拡張子は `.gitignore` でも除外されている。

### 下書き表記

- 自動生成の md は、1行目に「下書き（未照合）」を含むこと（保存時に1行目を検査し、含まれなければ保存しない）。照合なしに確定版を保存しない。

### 処理順序

- 処理ランの順序はコードで固定する：受信検証 → 文字起こし（2系統） → 話者合成（時系列マージ） → 作業用テキスト生成 → 状態を `awaiting_editing` へ。

### 話者マッピング

- 系統はファイル名で区別する（`system`＝相手、`mic`＝自分）。話者ラベルは、話者A＝マイク系統＝本人、話者B＝システム系統＝先方とする。

### データ領域と環境変数

- データ領域と保存先は、既定値に頼らず、必ず環境変数か設定で与える。`INTERVIEW_DATA_DIR` は状態・音声受信・ステージングを置くデータ領域のルート、`INTERVIEW_NOTES_DIR` は md 保存先（このリポジトリの `notes/` へのパス）とする。

### STTエンジン未接続時の扱い

- STTエンジンが未設定の場合は、`stt_not_configured` として `needs_reprocess` に残り、通知される。失敗を成功として扱わない。
